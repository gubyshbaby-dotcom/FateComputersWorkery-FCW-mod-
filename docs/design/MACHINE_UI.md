# Работа с машинами: загрузка руками, консоль, статус в мире

Статус: утверждено владельцем, реализация идёт (работы A и B, контракт —
[../MACHINE_CONTROL.md](../MACHINE_CONTROL.md)). Окно со слотами (`MachineScreen`) убирается
полностью, запасного варианта нет.

Полноэкранные программы поверх консоли (карта пластины, брак, отчёты) — отдельный документ:
[CONSOLE_APPS.md](CONSOLE_APPS.md); модель брака — [DEFECTS.md](DEFECTS.md).

Первая версия этого документа предлагала окна-пульты с экраном, картой пластины и слотами.
Она отклонена как перегруженная; её листы оставлены для истории:
`mockups/rejected_sheet_*.png`. Использовать их не нужно.

## 1. Принципы

1. **Предметы кладут в машину руками**, в то место, где они физически лежат: пластины на док,
   маску в порт масок, шихту в печь. Окон со слотами у машин нет. Положенный предмет сразу виден
   на машине.
2. **Пуск — рубильник.** Он уже есть у каждой машины. Больше для работы ничего не нужно.
3. **Пульт — настоящая текстовая консоль** 80×25, монохромная, с маленькой оболочкой:
   `status`, `start`, `stop`, `recipe`, `log`, `help`. Не дашборд: без рамок, таблиц, полос и
   цветного шума, один акцентный цвет.
4. **Автоматизация — с компьютера рядом**: `fcw machine <имя> <команда>` в Linux-ВМ, те же
   команды и тот же вывод.
5. **Состояние видно в мире**: световые линии, сигнальная лампа, двухстрочное табло на пульте,
   лампа на вводе питания. Чтобы понять, что с машиной, открывать ничего не надо.
6. Сдержанно: как пульт настоящего оборудования. Никаких голограмм, всплывающих панелей и
   лишнего свечения.

## 2. Физическая загрузка

### Общие правила

| действие | результат |
|---|---|
| ПКМ предметом по точке загрузки | вся стопка из руки уходит в машину (сколько поместится) |
| ПКМ пустой рукой по точке выдачи | одна стопка результата в руку |
| Shift + ПКМ пустой рукой по точке выдачи | весь результат в инвентарь; что не влезло, падает под ноги |
| ПКМ пустой рукой по точке загрузки | вернуть положенное (пока машина это не взяла в работу) |
| ПКМ по рубильнику | пуск и останов |
| ПКМ по пульту | открыть консоль |
| воронки, трубы, монорельс, манипуляторы | работают через те же порты, как сейчас |

Shift + ПКМ с пустыми обеими руками в ванили доходит до блока; если во второй руке есть предмет —
разрешить явно в `PlayerInteractEvent.RightClickBlock` (`setUseBlock(ALLOW)` для клеток машин).

**Как игрок понимает, куда что класть:**

- На корпусе у каждой точки уже есть физический признак: док, лоток, дверца, жёлоб — и короткая
  трафаретная надпись (`RETICLE`, `SN`, `WAFER IN`). Где надписи нет, её добавляет художник
  (см. [ARTIST_BRIEF.md](ARTIST_BRIEF.md)).
- При наведении прицела на точку контур выделения обводит не всю клетку, а саму точку (док, лоток):
  обычная ванильная рамка, только по форме зоны. Если в руке предмет, который сюда подходит,
  рамка белая; иначе стандартная тёмная. Свечения и стрелок нет.
- Над хотбаром появляется одна строка, как у ванильных подсказок: что это, сколько лежит,
  что сделает ПКМ. Примеры:
  - `Док 1: пластины 6/64  ·  ПКМ: положить`
  - `Порт масок: фотошаблон CPU, ресурс 187/256  ·  ПКМ: забрать`
  - `Лоток олова: пусто  ·  принимает олово`
  - `Док 2: пластины с рисунком ×8  ·  ПКМ: забрать, Shift+ПКМ: всё`
  Строка исчезает, как только прицел ушёл. Настройкой клиента её можно отключить.
- Звук: короткий и «железный». Положил — щелчок фиксатора (`block.iron_trapdoor.close`, тихо);
  забрал — ванильный `entity.item.pickup`; маска встала — двойной щелчок; рубильник — ванильный
  рычаг плюс удар контактора.

**Если предмет не подходит:** ничего не происходит с предметом, звучит глухой щелчок
(`block.dispenser.fail`), строка над хотбаром на 2 секунды сменяется причиной:
`Док принимает пластины`, `Док заполнен`, `Маска занята: идёт экспозиция`,
`Нет рецепта для этого предмета`. Частиц, красных вспышек и сообщений в чат нет.

**Что видно на машине:** движок уже показывает переносимые предметы клипов (props) и статичные
предметы по слотам (`MachineSpec.Display`). Каждой точке загрузки и выдачи нужен свой видимый
предмет; где модели уже есть — используем, недостающие перечислены в столбце «показ» и в ТЗ
художнику.

### Энергоблоки и автоматика

Тот же принцип, окон нет:

- Топливный генератор: ПКМ топливом по дверце топки; строка `Топка: уголь ×11, горит 48 с`.
- Шкаф ИБП: ПКМ модулем по двери ставит модуль на свободную полку; Shift + ПКМ пустой рукой
  вынимает; заряд виден на самих модулях.
- Подстанция и турбогенератор: рубильник и консоль с тем же набором команд.
- Манипулятор и станция монорельса: см. [AUTOMATION.md](AUTOMATION.md).

## 3. Консоль машины

ПКМ по пульту открывает текстовый экран 80×25. Это тот же рендер сетки символов, которым клиент
рисует экран `tty0` компьютеров (шрифт Terminus 8×16 из клиентской библиотеки), 640×400 px,
без рамок интерфейса вокруг: только экран на затемнённом фоне, `Esc` закрывает.

Цвета: фон `#0B0C0F`, текст `#C9CDD6`, один акцент `#A88BFF`. Акцентом выделяется только слово
состояния в `status` и слово `отказ` или `ошибка`. Курсор — блок, мигает раз в секунду.

Внутри не Linux, а оболочка машины на сервере: строка ввода, история стрелками, автодополнение
команд по `Tab`. Вывод короткий, построчный, без псевдографики.

### Команды (одни и те же на пульте и в `fcw machine`)

| команда | что делает |
|---|---|
| `status` | состояние, рецепт и такт, маска, загрузка по точкам, выход, питание |
| `start` | включить (то же, что рубильник). Если пуск невозможен — строка `отказ: …` |
| `stop` | остановить после текущего изделия; `stop now` — сразу, изделие в работе возвращается во вход |
| `recipe` | рецепты, доступные с тем, что загружено; текущий выбор |
| `recipe <имя>` / `recipe auto` | закрепить рецепт (машина берёт только его) или вернуть автовыбор |
| `log [n]` | последние n событий (по умолчанию 10, хранится 64) |
| `name [имя]` | показать или задать имя машины (по умолчанию `<тип>-<номер>`: `euv-1`, `eaf-1`) |
| `help` | список команд, по строке на команду |
| `mon`, `top`, `yield` | полноэкранные программы, см. [CONSOLE_APPS.md](CONSOLE_APPS.md) |
| `exit` | закрыть консоль (на пульте) |

С компьютера:

```
fcw machine list                     имена, типы и состояния машин, доступных этому компьютеру
fcw machine <имя> status [--json]
fcw machine <имя> start | stop [now]
fcw machine <имя> recipe [<имя рецепта> | auto]
fcw machine <имя> log [n] [--follow]
fcw machine <имя> wait <idle|run|fault> [--timeout <с>]
```

Вывод `fcw machine <имя> <команда>` совпадает с выводом на пульте строка в строку. Код возврата:
0 — выполнено, 1 — отказ (текст причины в stderr), 2 — машина не найдена или недоступна.
`--json`, `--follow` и `wait` есть только в `fcw`: это для скриптов.

Какие машины видит компьютер (решение владельца):

- машины, соединённые с ним **кабелем данных** (напрямую или через другие блоки сети);
- если в его сети есть **роутер** — ещё и все машины в радиусе роутера, без кабеля.

В `fcw machine list` у каждой машины указано, как она видна: `cable` или `radio`. Роутер — бытовой
`fcw:router` из первого набора моделей (три антенны); радиус — в контракте, модель кабеля данных —
в [ARTIST_BRIEF.md](ARTIST_BRIEF.md).

### Примеры сессий

Литограф:

```
FCW machine console   euv-1: литограф EUV Mk2
Введите 'help' для списка команд.

euv-1> status
состояние  работа: экспозиция, поле 24/61
рецепт     wafer_cpu  468/1200 t  2048 FE/t
маска      reticle_cpu  ресурс 187/256
загрузка   dock1: silicon_wafer x6   tin: tin_ingot x16
выход      dock2: wafer_cpu x2
питание    312k/400k FE  приход 2048 FE/t

euv-1> stop
останов после текущей пластины... ожидание

euv-1> recipe
wafer_cpu   silicon_wafer + tin_ingot -> wafer_cpu   1200 t  2048 FE/t
выбор: auto (по маске)

euv-1> log 3
14:18:41  ожидание: нет пластин
14:19:52  пуск wafer_cpu
14:20:31  останов оператором
```

Пуск без маски:

```
euv-1> start
отказ: нет маски. Вставьте фотошаблон в порт RETICLE.
euv-1> status
состояние  ошибка: нет маски
загрузка   dock1: silicon_wafer x8   tin: tin_ingot x16
выход      dock2: пусто
питание    400k/400k FE  приход 0 FE/t
```

Выход заполнен:

```
euv-1> status
состояние  ошибка: выход заполнен (dock2)
рецепт     wafer_cpu  1200/1200 t  2048 FE/t
...
```

Со стороны компьютера (скрипт смены):

```
$ fcw machine list
euv-1   литограф EUV Mk2     ожидание
eaf-1   дуговая печь         работа
line-1  линия электроники    ошибка: выход заполнен (out)
$ fcw machine euv-1 recipe wafer_memory && fcw machine euv-1 start
$ fcw machine euv-1 wait idle --timeout 600 && fcw machine line-1 start
$ fcw machine eaf-1 status --json
{"name":"eaf-1","type":"arc_furnace","state":"run","detail":"melt","recipe":"metallurgical_silicon",
 "ticks":148,"total":400,"energy":280000,"capacity":400000,"in":256,
 "load":{"charge":[{"id":"minecraft:quartz","count":28},{"id":"minecraft:coal","count":14}]},
 "out":{"tap":[{"id":"fcw:metallurgical_silicon","count":6}]}}
```

Язык (решение владельца): команды и имена предметов всегда английские; пояснения — на языке
клиента. Пульт передаёт язык игрока, `fcw machine` — язык из `LANG` гостя; переводит сервер
(строки оболочки лежат в данных мода). Для скриптов есть `--json`.
Строки состояния: `выключена`, `ожидание`, `работа: <фаза>`, `ошибка: <причина>`.

Причины ошибок (они же в журнале и на табло): `нет питания`, `выход заполнен (<точка>)`,
`нет маски`, `маска изношена`, `нет сырья` (это не ошибка, а пояснение к ожиданию).

## 4. Статус в мире

| что | где | состояния |
|---|---|---|
| световые линии и юбка цоколя | по всему корпусу (есть) | тёмные — выключена; белые — ожидание; фиолетовые — работа |
| сигнальная лампа | на пульте или на крыше над ним, 1 клетка | погашена; красная мигает (1 Гц) — ошибка или нет питания |
| табло | на стекле пульта, 2 строки × 16 знаков | строка 1 — состояние, строка 2 — подробность |
| лампа ввода | у порта `power` | погашена — питания нет; белая — питание есть |

Решение владельца: в первой очереди ошибку показывают сигнальная лампа и табло. Красное мигание
световых линий целиком — позже: оно требует четвёртого набора текстур `fault` у каждой машины.

Табло: монохромный текст тем же шрифтом Terminus, светлый на чёрном стекле, без рамки. Примеры:

```
РАБОТА           ОЖИДАНИЕ         ОШИБКА           ВЫКЛ
ПОЛЕ 24/61  39%  НЕТ ПЛАСТИН      НЕТ МАСКИ
```

Табло читается с 6–8 блоков; ближе игрок и так видит, что лежит в доках. Энергию отдельной шкалой
на машине не показываем: есть лампа ввода, а запас виден на ИБП (полоски заряда на модулях).

Звук: при переходе в ошибку один короткий сигнал (не сирена), дальше тишина.

## 5. Простые машины

Печь, ростовая печь, резка работают без консоли вообще: положил шихту в проём, дёрнул рубильник,
забрал слитки из лотка. Пульт у них есть и открывает ту же консоль — для тех, кто хочет посмотреть
журнал или закрепить рецепт. Табло и лампа такие же, как у литографа.

## 6. ТЗ программисту

### Взаимодействие

- `MachineSpec`: к `PortRole` добавить зону взаимодействия: список клеток и прямоугольник на грани
  (в 1/16 блока, координаты структуры), ключ названия (`interact.fcw.euv.dock1`), роль
  (вход, выход, катализатор), подсказку «что принимает». Зоны берутся из README и манифестов
  (`ports[].pos`), размеры уточняет художник.
- `MachineCellBlock.useItemOn` / `useWithoutItem`: по `BlockHitResult` найти зону; предмет в руке →
  вставка в слоты участка (те же `MachineRecipes.isInput` / `isCatalyst`, что у автоматики);
  пустая рука → выдача. Отказ — `displayClientMessage(…, true)` (строка над хотбаром) и звук.
- Форма выделения: `getShape` клетки при наведении возвращает зону (или рисовать контур в
  `RenderHighlightEvent.Block`). Белый контур — если предмет в руке проходит фильтр зоны.
- Подсказка при наведении: клиентский оверлей (слой над хотбаром), данные — из синхронизируемой
  блок-сущности: содержимое слотов по зонам уже нужно клиенту для показа props.
- Меню со слотами (`MachineMenu`, `MachineScreen`) удалить полностью, без настройки и запасного
  входа.

### Консоль

- Оболочка на сервере: `MachineShell.execute(machine, строка) → List<String>` — единственная
  реализация команд; её же вызывает обработчик сообщений агента для `fcw machine`.
- Экран: `MachineConsoleScreen` — сетка 80×25 поверх затемнения; ввод строки, история, `Tab`.
  Рендер сетки — тот же, что у `tty0` (клиентская библиотека, шрифт `terminus-uni2-8x16.psf`);
  от библиотеки нужен вход «нарисовать сетку из буфера ячеек» без демона. Если это неудобно —
  тот же PSF читается из Java и рисуется в `DynamicTexture` 640×400 (около 60 строк кода).
- Пакеты: клиент → сервер `MachineCommandPayload(pos, строка)`; сервер → клиент
  `MachineOutputPayload(pos, строки, акценты)`. Акцент — диапазон столбцов в строке, не более
  одного на строку.
- Данные для команд: состояние и причина (расширить `Status`: добавить `NO_CATALYST`,
  `CATALYST_WORN`), идентификатор текущего рецепта, такт, закреплённый рецепт, средний приход FE
  за 20 тиков, журнал — кольцевой буфер 64 записей `(gameTime, код, аргумент)` в NBT блок-сущности,
  имя машины.
- `fcw machine`: агент гостя шлёт сообщение в мир, мод отвечает текстом и кодом возврата.
  `wait` и `log --follow` — подписка: мод шлёт событие при смене состояния и при новой записи.

### Статус в мире

- Сигнальная лампа и лампа ввода — клетки-люки нового вида `lamp` (два варианта blockstate,
  `open` = горит); переключает код, игрок их не трогает.
- Табло: в манифест добавить `readouts`: `[{id, cell, face, rect, cols, rows}]`;
  `BlockEntityRenderer` рисует две строки тем же шрифтом (атлас из PSF), яркость полная, без
  теней. Текст меняется не чаще 4 раз в секунду.
- Синхронизация для табло и подсказок: состояние, причина, прогресс (0…1000), счётчики слотов по
  зонам — в пакете обновления блок-сущности, раз в 10 тиков и при изменении состава слотов.

### Порядок работ

1. Зоны взаимодействия, вставка и выдача рукой, подсказка и контур (сначала на печи).
2. Сигнальная лампа, лампа ввода, табло.
3. `MachineShell`, консоль на пульте.
4. `fcw machine` через агента, `wait` и `--follow`.
5. Удаление окна со слотами.
