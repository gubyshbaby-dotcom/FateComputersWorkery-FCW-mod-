# Производство комплектующих: контракт (v1)

Первая версия производственной цепочки: от кварца до процессоров, памяти и
плат, из которых собираются компьютеры. Только машины, для которых есть
готовые модели автора: дуговая печь, ростовая печь, участок резки и
полировки пластин, литограф EUV Mk2, линия электроники. Остальное из плана
(мехобработка, химия и газы, алмазы, инфраструктура, литографы младших
поколений, чистая комната, управление машинами с компьютера) — следующие
версии.

| литограф EUV Mk2 + блоки для его постройки | `scratchpad/all1/04_euv_scanner_mk2`, `scratchpad/all1/02_parts_kit` |
| дуговая печь v4 | `scratchpad/all2/05_arc_furnace` |

## Цепочка

```
кварц + уголь ──дуговая печь──► технический кремний ──дуговая печь (рафинирование)──► поликремний
железо + уголь ──дуговая печь──► сталь
поликремний ──ростовая печь──► монокристалл (слиток)
слиток ──резка и полировка──► полированные пластины
пластина + фотошаблон ──литограф EUV──► пластина с рисунком (тип по шаблону)
пластина с рисунком ──линия: корпусировка──► микросхемы (процессоры, память, контроллеры)
заготовка платы + микросхемы ──линия: сборка плат──► мат. плата, видеокарта, модули памяти
```

Младшие процессоры и память (DIP, QFP, SIMM, микросхема памяти DIP) крафтятся
на верстаке без машин — чтобы первый компьютер можно было собрать сразу.

## Рецепты машин

Тип рецепта `fcw:<машина>`: `fcw:arc_furnace`, `fcw:crystal_puller`,
`fcw:wafering`, `fcw:lithography`, `fcw:chip_packaging`, `fcw:pcb_assembly`.
Все одного класса (`com.fatecomputers.fcw.production.recipe.MachineRecipe`), JSON:

```json
{
  "type": "fcw:arc_furnace",
  "inputs": [ {"ingredient": {"item": "minecraft:quartz"}, "count": 4},
              {"ingredient": {"tag": "minecraft:coals"}, "count": 2} ],
  "catalyst": {"item": "fcw:reticle_cpu"},
  "results": [ {"id": "fcw:metallurgical_silicon", "count": 2} ],
  "ticks": 400,
  "energy_per_tick": 256
}
```

`catalyst` необязателен: не расходуется, но теряет 1 прочности, если у
предмета есть прочность. `results` могут иметь `"chance"` (0..1).

API для машин (делает агент материалов):

```java
// com.fatecomputers.fcw.production.recipe
public final class FcwRecipes {           // регистрация RecipeType и RecipeSerializer
    public static Supplier<RecipeType<MachineRecipe>> ARC_FURNACE, CRYSTAL_PULLER, WAFERING,
        LITHOGRAPHY, CHIP_PACKAGING, PCB_ASSEMBLY;
}
public record MachineRecipe(List<SizedIngredient> inputs, Optional<Ingredient> catalyst,
        List<ChanceResult> results, int ticks, int energyPerTick,
        RecipeType<MachineRecipe> type) implements Recipe<MachineRecipeInput> {
    // type: шестой компонент, которого не было в первой редакции контракта. Класс один на шесть
    // типов, а getType() должен знать свой; его проставляет сериализатор, в JSON поля нет.
    public List<ItemStack> rollResults(RandomSource random);  // выходы одного цикла с учётом шансов
    public List<ItemStack> maxResults();                      // все выходы по максимуму: под что нужно место
    public long totalEnergy();                                // ticks * energyPerTick
}
public record ChanceResult(ItemStack stack, float chance) {}
public record MachineRecipeInput(List<ItemStack> inputs, ItemStack catalyst) implements RecipeInput {}
public final class MachineRecipes {
    // Ещё: all(level, type), isInput(level, type, stack), isCatalyst(level, type, stack) — для
    // фильтров слотов. Из подходящих рецептов find берёт самый конкретный (больше разных входов,
    // затем больше предметов). В рецептах v1 не больше 4 разных входов и 2 разных выходов.
    /** Первый рецепт этого типа, который можно выполнить из содержимого входных слотов. */
    public static Optional<RecipeHolder<MachineRecipe>> find(Level level, RecipeType<MachineRecipe> type,
            List<ItemStack> inputs, ItemStack catalyst);
    /** Списать входы (и прочность катализатора) из слотов. */
    public static void consume(MachineRecipe r, List<ItemStack> inputs, ItemStack catalyst);
}
```

Линия электроники — одна машина с двумя участками: корпусировка
(`fcw:chip_packaging`, порт `wafer` → порт `chips`) и сборка плат
(`fcw:pcb_assembly`, порт `boards` + микросхемы → порт `out`).

## Машины (делает агент машин)

- Один движок на все машины, по данным из манифестов и файлов анимаций:
  блоки клеток `<машина>_part` и `<машина>_hatch` (свойства из README), блок
  управления в клетке пульта (`terminal`), порты по манифесту (предметы — Item
  Handler, энергия — Energy Storage NeoForge, жидкости — Fluid Handler),
  рубильник, люки, состояния off / idle / run, BlockEntityRenderer подвижных
  частей и переносимых предметов по клипам, частицы по описаниям эмиттеров.
- Постройка (дизайн: `docs/design/MACHINE_BUILD.md`; ведомости и рецепты компонентов:
  `docs/PRODUCTION_RECIPES.md`, раздел «Постройка машин»):
  - Проект `fcw:<машина>_blueprint` (дёшев) ставит стройплощадку: леса во всех клетках
    будущей машины и поддон на месте пульта. Поддон — это уже пульт машины в состоянии
    `site`: у площадки сразу есть имя, журнал, консоль и место в сети компьютера.
  - Компоненты завозят на поддон или на леса: ПКМ предметом, воронки и трубы (поддон —
    приёмник предметов), сразу для всех этапов, но не больше ведомости. Shift + ПКМ пустой
    рукой по поддону возвращает последнюю завезённую стопку; ПКМ пустой рукой открывает
    консоль (`status`, `bom`, `stage`, `log`, `cancel`).
  - Этап начинается сам, когда закончен предыдущий и его компоненты на месте; клетки
    появляются снизу вверх с искрами. После последнего этапа 30 с пусконаладки, затем
    разблокируется рубильник. Энергия на сборку (64 FE/т) нужна только при
    `production.requirePower`; на уровне `fab` — 256 FE/т всегда.
  - Литограф: либо проект и блоки набора деталей на площадку, либо блоки руками по схеме
    `euv_scanner_mk2_pattern.json` и ПКМ по `euv_controller` — тогда после проверки идёт
    только пусконаладка (600 с).
  - Разбор: `fcw:wrench`, Shift + ПКМ по пульту выключенной машины, второй раз для
    подтверждения. Содержимое выпадает сразу, этапы идут в обратном порядке за половину
    времени, возвращается 75 % компонентов (шкафы управления и проект — всегда). Ключ по
    площадке отменяет стройку или, если она разбирается, возобновляет её. Киркой клетки
    машины не ломаются.
  - Уровень `production.difficulty`: `standard` — четверть ведомости и времени, возврат
    100 %; `engineer` — как в таблицах; `fab` — время ×2, возврат 60 %, чипы с верстака не
    заменяют чипы литографа (рецепты компонентов уровня `fab` пока те же, что на `engineer`).
  - Старые комплекты `*_kit` работают как проект, у которого все компоненты уже завезены.
  - Данные: `data/fcw/construction/<машина>.json` (этапы, время, компоненты) генерирует
    `mod/tools/production/gen.py` из `build_data.py`; клетки делятся между этапами по доле
    времени, снизу вверх.
- Энергия: FE через порт `power`. Настройка сервера `production.requirePower`
  (по умолчанию false: без источника FE машины работают от «встроенного
  трансформатора», чтобы цепочка была проходима без других модов); при true
  — только от FE.
- Applied Energistics 2 (необязательно): если мод установлен, порт `power`
  становится узлом ME-сети. Подведите к нему ME-кабель; при
  `production.requirePower = true` работающая машина пополняет свой буфер из
  энергии сети по курсу AE2 (1 AE = 2 FE). Код в
  `production/machine/compat/ae2`, без AE2 он не загружается. Для проверки в
  разработке: `./gradlew runClient -Pfcw.withAe2`.
- Фильтры: во входы попадает только то, что используют рецепты этого участка,
  в порт масок только фотошаблоны; правило одно для рук и для портов. Участок
  сборки плат берёт микросхемы и из своего магазина, и прямо из лотка
  корпусировки. Рецепт стартует, как только загружено всё нужное; если
  подходит несколько, выбор делает `recipe <имя>` на пульте.
- Жидкости в v1 не обязательны: порты принимают жидкости (вода, аргон,
  охлаждение…), но рецепты их не требуют.
- Взаимодействие (дизайн: `docs/design/MACHINE_UI.md`, контракт:
  `docs/MACHINE_CONTROL.md`). Окна со слотами у машин нет.
  - Загрузка руками в точках машины (`MachineSpec.Zone`): ПКМ предметом кладёт
    стопку, ПКМ пустой рукой забирает одну стопку, Shift + ПКМ — всё. Точки:
    литограф — док 1 (пластины), док 2 (выдача), порт масок, лоток олова;
    дуговая печь — проём зонта (двери откроются сами; забрать шихту обратно:
    Shift + ПКМ) и лоток у ковша; ростовая печь — загрузочный люк и дверь
    выгрузки; резка — подача слитка и кассета; линия — вход пластин, лоток
    микросхем (сюда же докладывают микросхемы для сборки), магазин плат, выход.
  - При наведении: строка над хотбаром (что это, что лежит, что сделает ПКМ) и
    белая рамка, если предмет в руке сюда подходит. Отказ: глухой щелчок и
    причина той же строкой на 2 с. Строку отключает `machines.hints` в конфиге
    клиента.
  - Пульт: ПКМ открывает текстовую консоль 80×25 (шрифт Terminus из того же PSF,
    что у `tty0`). Команды исполняет сервер в `MachineShell`: `status`, `start`,
    `stop [now]`, `recipe [имя|auto]`, `log [n]`, `name [имя]`, `help`; `exit`
    закрывает. Тексты оболочки по языкам лежат в `data/fcw/shell/<lang>.json`.
    Для скриптов: `--json` у `status`, `recipe`, `log` и `log --since <seq>`.
  - У машины есть имя (`euv-1`, `eaf-2`…, уникально в мире) и журнал на 64
    события; оба хранятся в пульте.
  - В мире: табло 2×16 и сигнальная лампа на пульте (мигает красным при ошибке:
    нет питания, выход заполнен, нет маски), лампа у ввода питания. Пока нет
    моделей художника, их рисует рендерер пульта.
- Работа: рецепт ищется по `MachineRecipes.find`, время = `ticks`, во время
  работы state = run и проигрываются клипы машины (рост кристалла растянут на
  время рецепта, такт линии — циклически и т.д.), без рецепта idle, рубильник
  выключен — off.

## Брак

Дизайн: `docs/design/DEFECTS.md`. Здесь — что сделано в моде (пакет `production/quality`).

Модель включена на уровнях `production.difficulty` = `engineer` и `fab`; на `standard` брака нет,
классы не ставятся, корпусировка даёт число из рецепта. Уровень `fab` пока считает так же, как
`engineer`: место расширения (скрытый брак, метрология, сортировка — DEFECTS.md, раздел 10) —
`Quality.enabled()` и `MachineQuality.decide`.

- **Карта пластины**: 61 поле (строки 3-7-7-9-9-9-7-7-3), экспонируются змейкой равномерно по времени
  рецепта литографа. Каждое поле либо годное (`.`), либо получает одну причину:

  | Код | Причина | Вероятность на поле | Чем лечится |
  |---|---|---|---|
  | `P` | частица | под открытым небом 16 %, в закрытом помещении (ISO 8) 9 %, ISO 7 / 6 / 5 — 5 / 2,5 / 1 % | стены и потолок, фильтры |
  | `W` | полировка | пластина класса A / B / C — 1 / 4 / 8 %; на краю ×1,6, в середине ×0,6 | вода на резке, APC |
  | `C` | кристалл | слиток класса A / B / C — 0,5 / 3 / 6 % | вода и ровное питание ростовой печи |
  | `E` | питание | литограф встал без энергии: потеряно текущее поле и два следующих | буфер, ИБП |
  | `T` | перегрев | нет воды в порту `coolant_in`: 7 % в среднем, от ×0,5 в начале пластины до ×1,5 в конце | вода, APC |
  | `M` | износ маски | после половины ресурса фотошаблона растёт линейно до 12 % | новый шаблон, APC |
  | `V` | вибрация | рядом работает тяжёлая машина: 5 % | расстояние, APC |

- **Помещение**: раз в 5 с от клеток литографа идёт заливка по воздуху (до 8192 блоков). Вышла под
  небо или не уложилась — «открыто»; иначе ISO 8. Чище ISO 8 помещение делают блоки тега
  `#fcw:cleanroom_filters` на его границе: один на 64 блока воздуха — ISO 7, на 32 — ISO 6, на 16 —
  ISO 5. Своего блока фильтра в моде пока нет (тег пуст), двери не учитываются.
- **Вода**: обычная вода в баке порта `coolant_in` (литограф, ростовая печь) или `water` (резка),
  1 мБ за тик работы. Заливается ведром (ПКМ по клетке порта) или трубами.
- **Вибрация**: работающая дуговая печь ближе 16 блоков, резка ближе 8, ростовая печь в фазе
  выгрузки ближе 8.
- **Классы сырья** A / B / C (компоненты `fcw:crystal_grade`, `fcw:polish_grade`): слиток — A, если
  печь работала с водой и без остановок по питанию, B при одном нарушении, C при двух; пластина
  наследует класс слитка и получает класс полировки по тем же правилам на резке.
- **Класс годности** пластины с рисунком (компонент `fcw:yield_class`) и выход корпусировки:

  | Класс | Годных полей | Множитель выхода |
  |---|---|---|
  | S | 58–61 | ×1,25 |
  | A | 52–57 | ×1 |
  | B | 43–51 | ×0,8 |
  | C | 31–42 | ×0,6 |
  | D | до 30 | ×0,4 |

  Множитель применяется ко всем результатам рецепта корпусировки, дробная часть разыгрывается.
  В предмете хранится только класс: одинаковые стопки складываются. Полные карты последних
  64 пластин лежат в пульте литографа. Подсказка предмета показывает класс.
- **APC** (расчёт поправок компьютером). Компьютер, связанный с машиной (`MachineLinks`), раз в
  секунду отдаёт ей вычислительные единицы по процессору: `cpu_dip` 0,5, `cpu_qfp` 1, `cpu_pga` 2,
  `cpu_lga` 4, `cpu_multicore` 8, `cpu_server` 16 CU. Служба `fcw apc` в госте работает — 100 %,
  ВМ выключена или службы нет — 75 %, связи нет — 0. Нужно: литограф 2 / 4 / 8 CU по ступени
  рецепта, ростовая печь 2, резка 1, линия 4. Покрытие c = получено / нужно (не больше 1):
  литограф — `M`, `T`, `V` ×(1 − 0,6c), `W` ×(1 − 0,3c); ростовая печь и линия — время рецепта
  ×(1 − 0,2c); резка — девятая пластина со слитка с шансом c. CU одного компьютера делятся поровну
  между его машинами, если служба не задала доли.
- **Пульт**: `status` показывает годность последней пластины с причинами, идущую карту, среду
  (помещение, вода, вибрация) и APC; `yield` — отчёт за смену (игровые сутки, сегодня и вчера):
  пластины, годность, классы, причины, простои. `status --json` — полный снимок машины
  (`machine_frame` из `docs/design/CONSOLE_APPS.md`): к прежним полям добавлены `kind`, `reason`,
  `phase`, `log_seq`, `defects`, `apc`, `litho` (или `env` у остальных машин), `shift`, а для
  консольных программ — `use` (расход сейчас, FE/t) и `sections` (состояние, рецепт и ход каждого
  участка); у пластин в `lot_wafers` есть `time`.
- **Программы на компьютере** (`fcw top`, `fcw litho`, `fcw yield`, …, служба `fcw apc`) показывают
  всё это полноэкранно: `docs/design/CONSOLE_APPS.md`, протокол — `docs/CONTRACT.md` §7.
- Журнал: `wafer` (класс и число годных), `brownout`, `room` (смена класса помещения), `apc`.

## Сеть данных и компьютеры

Подробности — `docs/MACHINE_CONTROL.md`.

- `fcw:data_cable` (кабель данных) соединяет корпус компьютера с любой клеткой машины;
  `fcw:router` в этой сети добавляет все машины, чей пульт в радиусе `production.routerRadius`
  (32) блоков. В госте: `fcw machine list`, `fcw machine <имя> status` и т.д.
- При `production.requirePower = true` компьютеры тоже потребляют FE (или энергию ME-сети):
  12 FE/t + 6 за ядро + 2 за ГиБ памяти + 16 за видеокарту. Пять секунд без энергии — и
  машина выключается (или встаёт на паузу: `computers.onPowerLoss`).
