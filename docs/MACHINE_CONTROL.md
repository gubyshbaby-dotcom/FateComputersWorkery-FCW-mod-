# Управление машинами: контракт между работами

Дизайн взаимодействия — `docs/design/MACHINE_UI.md`. Здесь — то, что делят между собой
три работы, которые идут параллельно, и решения владельца проекта.

## Решения (утверждены)

1. Ошибка в мире: сначала сигнальная лампа и табло на пульте; красное мигание световых линий — позже.
2. Компьютер видит машину, если она соединена с ним **кабелем данных**; если в его сети есть
   **роутер** — ещё и все машины в радиусе роутера без кабеля.
3. Компьютеры потребляют FE, но только при `production.requirePower = true`.
4. Биотопливо — позже.
5. AE2: порт `power` сам принимает энергию сети (как сейчас), отдельного блока нет.
6. Монорельс: сейчас поворотный круг 1×1, стрелка с пером — позже.
7. FOUP (кассета пластин как предмет) и жидкости в капсулах монорельса — в первой очереди.
8. Консоль: текст на языке клиента, команды всегда английские.
9. Старое окно со слотами убрать полностью.
10. Демо-завод 103×47 для начала, но отделан как постройка профессиональных билдеров.
11. Помимо простой консоли нужны **программы** (`fcw-…`): полноэкранные консольные приложения с
    выразительным, но не перегруженным оформлением — карта пластины с прогрессом по полям, брак,
    журнал и т.п., на нескольких экранах (вкладках). Запускаются и с компьютера (настоящие бинарники
    в госте), и из консоли пульта.

Вторая серия (по `docs/design/DEFECTS.md`, `CONSOLE_APPS.md`, `HARDCORE.md`):

12. Нынешние числа рецептов = класс годности **A** (новичок получает около 60 %, вершина 125 %).
13. APC: CU считаются по установленному процессору компьютера, связанного с машиной. Полная
    мощность — пока ВМ включена и в ней работает служба `fcw apc`; если ВМ выключена или служба не
    работает — **75 %** от максимума. Настоящей нагрузки на CPU хоста нет.
14. Класс частоты процессора ограничивает долю CPU хоста у ВМ (доработка демона).
15. Три уровня сложности `standard` / `engineer` / `fab`, по умолчанию `engineer`.
16. Программы доступны и как `fcw litho`, и как `fcw-litho` (ссылки).
17. Младшие литографы (контактная печать, i-line) компактные; DUV и иммерсия — крупные.
18. Сырьё на уровне `fab`: своё обогащение, продукты GT / Mekanism / Create / Oritech принимаются
    через теги.
19. Свои декоративные блоки (архив 14) заказываются после архивов 11–13.
20. Урон от опасностей — отдельная настройка, по умолчанию включена на уровне `fab`.

Постройка машин (`docs/design/MACHINE_BUILD.md`), по рекомендациям:

21. Первый литограф на `standard` / `engineer` можно собрать на чипах с верстака в тройном
    количестве; на `fab` — только на чипах своей линии.
22. Многослойное зеркало из аметиста до уровня `fab`; молибден — на `fab`.
23. Разбор возвращает 75 % всех компонентов, без исключений.
24. Старые комплекты в существующих мирах превращаются в проект с полным набором компонентов.
25. Энергия на сборку (64 FE/t) — только при `requirePower`.
26. `standard` — четверть ведомости.

Уровень сложности — одна настройка сервера `production.difficulty = standard | engineer | fab`
(по умолчанию `engineer`). Её вводит работа «постройка машин»; брак и остальное читают её же.

## Кто чем владеет

| работа | владеет | не трогает |
|---|---|---|
| **A. Машины в мире** | загрузка ПКМ и подсказки, удаление окна со слотами, консоль пульта, `MachineShell` (реализация), имена машин, журнал машины, лампа и табло | `MachineLinks`, блоки сети, компьютеры, Rust |
| **B. Сеть данных и компьютер** | кабель данных, роутер, `MachineLinks` (реализация), мост агента в моде (`machine_req` → `MachineShell`), `fcw machine` в госте (Rust, `fcw-agent`), потребление FE компьютерами | `MachineShell` (только вызывает), пакет `production/machine` кроме `net/` |
| **C. Программы и брак** | сначала дизайн (`docs/design/`), потом реализация после утверждения | — |

Заглушки обоих классов уже в репозитории; владелец заменяет тело, сигнатуры не меняет без правки
этого файла.

## Java API

```java
// production/machine/shell/MachineShell.java — владелец A
public record Result(int exit, String text, @Nullable JsonObject json) {}   // exit: 0 ok, 1 отказ машины, 2 ошибка команды
public static Result exec(MachineControllerBlockEntity machine, String line, String lang, boolean json, String actor);
public static String name(MachineControllerBlockEntity machine);            // «euv-1», уникально в мире

// production/machine/net/MachineLinks.java — владелец B
public static List<MachineControllerBlockEntity> reachable(ServerLevel level, BlockPos computerPos);
public enum Via { CABLE, RADIO }
public record Link(MachineControllerBlockEntity machine, Via via) {}
public static List<Link> links(ServerLevel level, BlockPos computerPos);    // то же, с пометкой для list
```

Сеть данных (`production/machine/net/`): `fcw:data_cable` и `fcw:router` — блоки без блок-сущностей.
`MachineLinks` обходит сеть в ширину от корпуса компьютера по соседству граней: узлы — кабели и
роутеры, только загруженные чанки, не больше 4096 узлов. Машина видна по кабелю (`cable`), если любая
её клетка касается узла сети или самого корпуса; по радио (`radio`) — если её пульт не дальше
`production.routerRadius` (32) блоков от любого роутера этой сети (учитывается до 32 роутеров).
Машина, видимая обоими способами, считается кабельной. Чужие компьютеры сеть не продолжают.
Роутер — готовая модель набора 01 (`router` / `router_on`): `powered = true`, когда он касается кабеля
данных или корпуса компьютера, то есть подключён и работает. Модель кабеля данных временная
(`mod/tools/network/gen.py`), настоящая заказана художнику. Оператору: `/fcw net <x y z компьютера>`
показывает, какие машины видит компьютер и как.

Мост — `MachineBridge` (тот же пакет), по экземпляру на компьютер: `machine_req` из
`ComputerBlockEntity.onAgentMessage` → `MachineShell` → `machine_resp`. Частота запросов одной ВМ
ограничена (`production.machineRequestsPerSecond`, по умолчанию 20, запас на 2 с): лишние получают
`exit` 2 «слишком много запросов», а если гость не унимается — остаются без ответа. Список машин
компьютера кэшируется на 10 тиков. `actor` = имя компьютера в сети гостей (`fedora-1.mc`).

`exec` вызывается на сервере в главном потоке. `line` — команда без имени машины (`status`,
`recipe auto`, `log 5`). `lang` — код языка клиента (`ru_ru`, `en_us`); сервер переводит сам (на
выделенном сервере нет ассетов клиента — строки оболочки лежат в данных мода). `actor` пишется в
журнал машины («оператор Steve», «fedora-1.mc»).

## Агент гостя: сообщения `machine_*`

Поверх существующего канала `fcw.agent` (строки JSON, `AgentSend` / `AgentMessage`, демон не
меняется). Строка не длиннее 64 КиБ.

гость → хост:

```json
{"type":"machine_req","id":17,"op":"list","json":true,"lang":"ru_ru"}
{"type":"machine_req","id":18,"op":"exec","machine":"euv-1","line":"status","json":false,"lang":"ru_ru"}
```

хост → гость:

```json
{"type":"machine_resp","id":18,"exit":0,"text":"состояние  работа: …","json":null}
```

- `list` — машины из `MachineLinks.links`: `json` = `{"machines":[{"name":"euv-1","kind":"euv_scanner_mk2","state":"run","link":"cable|radio"}]}`,
  `state` = `off | idle | run | fault`; `text` — по строке на машину: имя, тип, состояние (как в
  примере `fcw machine list` из MACHINE_UI.md), для пустой сети — «в сети этого компьютера нет машин».
  Список собирает мост, а не `MachineShell`.
- Ответ, который не помещается в строку агента (60 000 байт), урезается по тексту; если не помещается
  `json` — `exit` 2.
- Нет такой машины или она не видна: `exit` 2, текст «нет машины euv-9 в сети этого компьютера».
- Компьютер выключен или агент не ответил — ответа нет; CLI ждёт 5 с и пишет «агент не отвечает».
- `lang` CLI берёт из `LC_ALL` / `LC_MESSAGES` / `LANG` гостя (`ru_RU.UTF-8` → `ru_ru`), иначе `en_us`.
- `wait` и `--follow` CLI делает сам опросом `status --json` / `log --json` раз в секунду; для
  этого `log --json` отдаёт записи с возрастающим `seq`, а `log --since <seq>` — только новые.
  `wait <состояние>` сравнивает слово с полем `state` ответа `status --json` (`error` считается
  `fault`); код 0 — дождался, 1 — вышел `--timeout`, 2 — машины нет или мир молчит.
  `log [n] --follow` печатает `log [n]`, берёт наибольший `seq` из его `json` (в любом месте
  ответа) и дальше раз в секунду спрашивает `log --since <seq>`.
- Код выхода `fcw machine` = `exit` ответа; при `exit` ≠ 0 текст идёт в stderr. С `--json` в stdout
  печатается `json` ответа (если он есть), иначе текст.
- Подписка `machine_watch` / `machine_unwatch` → `machine_frame`, служба `apc_beat` и `op` = `yield`
  описаны в `docs/CONTRACT.md` §7 («Машины: APC, отчёт и подписка на снимки»); как ими пользуются
  программы `fcw top`, `fcw litho`, … и `fcw apc` — там же, «Программы: подписка и служба APC внутри гостя».

## Питание компьютеров

Только при `production.requirePower = true`; иначе всё как сейчас. Корпус принимает FE с любой
стороны (и от AE2, как машины). Расход зависит от конфигурации машины (ядра, память, видеокарта);
числа — в `docs/design/ENERGY_BLOCKS.md`, если там нет — предложить и записать туда. Без энергии:
предупреждение на экране, через 5 с жёсткое выключение ВМ (как у настоящего ПК — в этом и роль
ИБП). Настройка `computers.onPowerLoss = off | pause` (по умолчанию `off`).

Как сделано:

- Буфер корпуса 4 000 FE, приём до 1 000 FE/t (capability `EnergyStorage` у блок-сущности
  компьютера, все стороны). При `requirePower = false` буфер ничего не принимает.
- Расход, FE/t: `12 + 6 × ядра + 2 × ГиБ памяти (с округлением вверх) + 16 за видеокарту`; идёт,
  пока ВМ запускается или работает (на паузе и в выключенном виде — ноль).
- Включить компьютер можно, когда в буфере есть секунда работы; иначе ошибка «Нет питания».
- Энергия кончилась: в строке состояния окна компьютера и над хотбаром игроков в 16 блоках —
  «нет питания, выключение через 5 с». Вернулась за эти 5 с — предупреждение снимается.
- Через 5 с: `off` — `StopVm` с `force` (без ACPI); `pause` — `PauseVm` (QMP `stop`), а когда в
  буфере снова есть секунда работы — `ResumeVm`. Запросы паузы в `control.proto` уже были.
- AE2: корпус — узел ME-сети со всех сторон (`compat/ae2/Ae2ComputerPower`), буфер пополняется из
  энергии сети по курсу AE2; общая с машинами часть — `Ae2Compat.pull`.
