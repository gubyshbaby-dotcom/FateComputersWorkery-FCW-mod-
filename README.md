# Fate Computers Workery (FCW)

Мод для Minecraft Java 1.21.1 (NeoForge): в мире стоят настоящие компьютеры.
Внутри каждого своя виртуальная машина с Linux — Fedora 45, Ubuntu 26.04 LTS
или Arch Linux с готовым рабочим столом (labwc + панель LXQt), терминал —
Alacritty. Экран компьютера живой прямо на мониторе в мире; с клавиатурой и
мышью за компьютер можно сесть и работать. Компьютеры видят друг друга по
сети (`<имя>.mc`), выходят в интернет через NAT с файрволом и умеют управлять
редстоуном.

## Как устроено

```
 клиент игрока                сервер Minecraft              демон ВМ (Rust)                гостевая ВМ (QEMU)
 ┌──────────────┐  TCP MC    ┌────────────────┐  Unix-сокет ┌──────────────────┐  virtio     ┌───────────────────┐
 │ мод (Java)   │◄──────────►│ мод (Java)     │◄───────────►│ API управления   │◄───────────►│ labwc + lxqt-panel│
 │ блоки, GUI   │  токен     │ блоки, мост    │  protobuf   │ планировщик      │  gpu/input  │ Alacritty         │
 └──────┬───────┘            └────────────────┘             │ стример экранов  │  console    │ tty на hvc0       │
        │ JNI                                               │ текстовые экраны │  serial     │ агент мира (fcw)  │
 ┌──────┴───────┐        QUIC по UDP, напрямую              │ диспетчер ввода  │  snd, net   │ PipeWire, networkd│
 │ libfcw_client│◄─────────────────────────────────────────►│ QUIC-сервер      │  blk        └───────────────────┘
 │ кадры, текст │  кадры (дельты тайлов), текст, ввод, звук │ сеть: свитч, NAT │
 └──────────────┘                                           │ диски: база+слой │
                                                            └──────────────────┘
```

- Пиксели, звук и ввод идут мимо игрового тика: сервер Minecraft только
  выдаёт одноразовые токены, а клиент игрока сам подключается к демону по
  QUIC. Сертификат демона закреплён, отпечаток приходит от сервера.
- Демон запускает QEMU с virtio-устройствами. Ускорение: KVM (Linux), WHPX
  (Windows), HVF (macOS на Intel), иначе TCG — программная эмуляция, она
  работает везде, но медленно.
- Экран `gfx0` демон забирает у QEMU по VNC, режет на тайлы 64x64 и шлёт
  только изменения (RGBA + zstd). Экран `tty0` — консоль `hvc0`: демон ведёт
  эмулятор терминала, клиент рисует сетку шрифтом Terminus.
- Диск машины — тонкий слой qcow2 поверх общей базы образа. Версия образа
  закрепляется за машиной: если обновить образ, старые машины продолжат
  работать на своей версии, а в GUI появится «Обновить ОС».
- Сеть: userspace-свитч демона (без tap и root) — L2 между машинами, DHCP,
  DNS (`<имя>.mc`), NAT наружу. Файрвол не пускает гостей ни к сервисам
  хоста (RCON, базы, сам демон), ни в локальную сеть; есть лимит скорости.

Контракты между частями: [`docs/CONTRACT.md`](docs/CONTRACT.md); протоколы:
[`native/proto/`](native/proto).

## Что в репозитории

| каталог | что |
|---|---|
| `mod/` | мод NeoForge 1.21.1 (Java 21, Gradle, ModDevGradle), modid `fcw` |
| `native/crates/fcw-daemon` | демон ВМ: QEMU, QMP, VNC → тайлы, текстовые экраны, QUIC, токены, ввод, звук (Opus), агент, образы |
| `native/crates/fcw-net` | сеть гостей: L2-свитч, DHCP, DNS, NAT (smoltcp), файрвол, лимиты |

| `images/` | сборка гостевых образов и проверка их загрузки |

## В игре

**Блоки.** Компьютеры: системный блок и шесть корпусов (Desktop, Mini Tower,
Mid Tower, игровой, компактный, серверный 4U). Мониторы: ЖК и ЭЛТ.
Клавиатура, мышь, колонки (компьютерные, полочная, напольная, сабвуфер,
саундбар).

**Комплектующие** вставляются в GUI компьютера (ПКМ):

| деталь | что даёт |
|---|---|
| материнская плата | обязательна |
| процессор | vCPU: 8-бит DIP — 1, QFP — 1, PGA — 2, 64-бит — 2, многоядерный — 4, серверный — 8 (не больше ядер хоста) |
| память (до 4 модулей) | DIP 256 МБ, SIMM 512, DIMM 1024, DDR 2048, DDR RGB 4096, серверная 8192, SO-DIMM 2048 |
| видеокарта | рабочий стол; без неё только текстовая консоль |

Для рабочего стола нужно не меньше 1 ГБ памяти, рекомендуется 2 ГБ.

**Как пользоваться.**
1. Поставить компьютер, рядом монитор, клавиатуру и мышь: периферия сама
   привязывается к ближайшему компьютеру в радиусе 8 блоков. Перепривязать:
   Shift+ПКМ пустой рукой по компьютеру, затем Shift+ПКМ по периферии.
2. В GUI компьютера вставить детали, выбрать ОС и нажать «Включить».
   Компьютер, переименованный на наковальне, получит это имя в сети.
3. ПКМ по монитору или клавиатуре — сесть за компьютер (полный экран, ввод
   захвачен). Выйти — **правый Ctrl**. Клавиатура работает при привязанной
   клавиатуре, мышь — при привязанной мыши. Управляет один игрок; щелчок
   по экрану перехватывает управление.
4. Внутри: пользователь `user`, пароль `fcw` (есть sudo). Терминал —
   Super+Enter или Ctrl+Alt+T. Раскладки us/ru, переключение Alt+Shift.

**Редстоун.** Внутри гостя:

```bash
fcw redstone get
```

```bash
fcw redstone set top 15
```

Стороны считаются от самого компьютера: `front back left right top bottom`.

**Команды:** `/fcw status`, `/fcw images`, `/fcw images fetch <id>`, `/fcw vms`.

## Установка

1. Minecraft Java 1.21.1 + NeoForge 21.1.x, jar мода в `mods/`.
2. Там, где работает сервер (в одиночной игре — у самого игрока), нужен
   QEMU (`qemu-system-x86_64` и `qemu-img`):
   - Linux: Ubuntu/Debian — `qemu-system-x86 qemu-utils`, Fedora и Arch —
     `qemu-system-x86 qemu-img`; для скорости — доступ к `/dev/kvm`
     (группа `kvm`);
   - Windows: установщик QEMU + компонент «Платформа низкоуровневой оболочки
     Windows» для WHPX;
   - macOS: `brew install qemu`.
   Путь к QEMU можно указать в `config/fcw-server.toml` (`daemon.qemuPath`).
3. Образы: `/fcw images fetch fedora` (также `ubuntu`, `arch`) или вручную —
   распаковать `fcw-image-<id>.tar.zst` в `<папка игры>/fcw/images/`.
4. Для игры по сети открыть UDP-порт демона (по умолчанию 25600) и, если
   сервер за NAT, указать `daemon.publicHost`.

### Хостинг на Pelican / Pterodactyl (и других панелях на Docker)

Сервер там работает в контейнере без root, поставить QEMU пакетом нельзя.
Ничего ставить и не нужно: если демон не нашёл QEMU, мод сам скачивает
переносимый статический QEMU в `fcw/qemu/` (см. [`qemu/README.md`](qemu/README.md)).
Что настроить в панели:

1. **Порт.** Добавить серверу вторую аллокацию (порт, UDP должен быть
   открыт) и указать его в `daemon.quicPort`; в `daemon.publicHost` —
   адрес/домен узла, по которому игроки заходят на сервер.
   Если сервер за NAT и наружу его выводит frp (или проброс портов на
   роутере), то `daemon.publicHost` — внешний адрес, на который заходят
   игроки (машина с frps), `daemon.quicPort` — локальный порт демона
   (`localPort` в frpc), а `daemon.publicPort` — внешний (`remotePort`),
   если он отличается. В frpc нужен прокси с `type = "udp"`, TCP для
   QUIC не подходит. Пример для frpc.toml:

   ```toml
   [[proxies]]
   name = "fcw-quic"
   type = "udp"
   localIP = "127.0.0.1"
   localPort = 25600
   remotePort = 25600
   ```
2. **Память.** Память виртуальных машин считается в лимит контейнера:
   на каждый включённый компьютер с рабочим столом добавьте 1–2 ГБ сверх
   того, что нужно самому Minecraft (текстовому — от 256 МБ).
3. **Диск.** Образ ОС ~0.5–0.6 ГБ в архиве и ~1–1.5 ГБ распакованным, плюс
   копия на каждую используемую версию и диски машин. Закладывайте 5+ ГБ.
4. **CPU.** В контейнерах обычно нет `/dev/kvm`, поэтому машины работают в
   программной эмуляции (TCG): рабочий стол грузится 1–2 минуты и заметно
   медленнее, текстовая консоль — нормально. Если хостер может пробросить
   `/dev/kvm` в контейнер, демон сам включит KVM.

#### KVM через демон на узле (свой узел Pelican / Pterodactyl)

Wings не пробрасывает устройства в контейнеры, поэтому `/dev/kvm` в сервер
Minecraft не попадёт. Если у вас есть root на самом узле, демон с QEMU можно
запустить там как службу systemd с прямым доступом к KVM, а мод будет
подключаться к нему по TCP:

1. Поставить QEMU на узел (`apt install qemu-system-x86 qemu-utils` или
   аналог) — либо ничего не ставить: демон сам скачает переносимый QEMU в
   `/var/lib/fcw/qemu`.
2. Скопировать на узел jar мода и
   [`native/packaging/install-host-daemon.sh`](native/packaging/install-host-daemon.sh),
   запустить:

   ```sh
   sudo ./install-host-daemon.sh fcw-<версия>.jar [--control-addr 172.18.0.1:25700] [--quic-port 25600]
   ```

   Скрипт достаёт демон из jar в `/usr/local/bin/fcw-daemon`, создаёт
   пользователя `fcw` (группа `kvm`), каталоги `/var/lib/fcw/{images,vms,qemu}`
   и токен `/etc/fcw/token`, ставит и включает юнит `fcw-daemon.service`
   (пример: [`native/packaging/fcw-daemon.service`](native/packaging/fcw-daemon.service)).
   Без `--control-addr` берётся шлюз docker-сети `pelican_nw`
   (`pterodactyl_nw`, иначе `docker0`) — адрес узла, видимый из контейнеров.
3. Прописать в `config/fcw-server.toml` то, что напечатал скрипт:

   ```toml
   [daemon]
   mode = "remote"
   remoteAddress = "172.18.0.1:25700"
   remoteToken = "<содержимое /etc/fcw/token>"
   ```

   Мод не запускает свой демон, подключается к узлу (переподключается при
   обрыве) и при остановке сервера гасит свои машины.
4. Файрвол узла: TCP-порт управления (25700) открыть только для подсети
   контейнеров (`ufw allow from 172.18.0.0/16 to 172.18.0.1 port 25700 proto tcp`),
   UDP-порт игроков (`--quic-port`) — для всех. Игроки подключаются к демону
   на узле напрямую, `daemon.publicHost` — адрес узла.

Демон-служба не выходит при обрыве связи с модом, останавливается только
`systemctl stop fcw-daemon` (машины гасятся: ACPI, потом kill). Журнал:
`journalctl -u fcw-daemon -f`. Проверить без мода (fcw-probe собирается из `native/`):
`fcw-probe --control tcp://172.18.0.1:25700 --token-file /etc/fcw/token hello`.

Основные настройки сервера (`config/fcw-server.toml`): `daemon.*` (путь,
QEMU, порт, лимит машин, ускоритель), `vm.*` (язык и раскладки гостя,
размер экрана, лимит памяти), `network.*` (интернет, лимит скорости,
allow/deny), `access.*` (радиус привязки, только владелец).

## Сборка

Нативная часть (Rust 1.80+, для звука нужен cmake):

```bash
cargo build --release --manifest-path native/Cargo.toml
```

Агент гостя:

```bash
cargo build --release --manifest-path native/Cargo.toml -p fcw-agent --target x86_64-unknown-linux-musl
```

Мод (кладёт в jar нативы из `native/target/release` для текущей платформы и
из `-Pfcw.nativesDir=<каталог>/<os>-<arch>/` для остальных):

```bash
cd mod && ./gradlew build
```

Образы (Linux, root; внутри работает в своём mount namespace):

```bash
sudo FCW_AGENT_BIN=native/target/x86_64-unknown-linux-musl/release/fcw ./images/build-image.sh fedora
```

Проверка образа без демона и игры (скриншоты в рабочем каталоге):

```bash
python3 images/test-boot.py images/out/fedora /tmp/fcw-test --gpu --keys meta_l-ret
```

Проверка всего тракта без игры (демон → QEMU → QUIC):

```bash
native/target/release/fcw-probe --control /tmp/fcw/control.sock screenshot --vm my-pc --screen gfx0 --out shot.png
```

CI (`.github/workflows/`): `build.yml` — тесты, нативы для Linux
x86_64/aarch64, Windows x86_64, macOS arm64/x86_64 и jar мода (релиз по тегу
`v*`); `images.yml` — образы (релиз `images` по тегу `images-*`).

## Состояние

Проверено вживую (QEMU в TCG, без KVM):

- образы Fedora 45, Ubuntu 26.04.1 LTS, Arch Linux грузятся до рабочего
  стола labwc + lxqt-panel, Alacritty по Super+Enter, консоль `hvc0`;
- полный тракт демон → VNC → тайлы → QUIC → клиент: рабочий стол, ввод с
  клавиатуры и мыши, текстовый экран, звук (тон 440 Гц доходит до клиента);
- в игре: модели и GUI, живой экран на мониторе, полноэкранный режим с
  вводом, текстовая консоль на ЭЛТ, перехват управления, обновление ОС,
  редстоун в обе стороны (лампа от `fcw redstone set`);
- сеть: DHCP, `<имя>.mc`, ping и HTTP между машинами, интернет, отказ для
  локальных адресов и адресов хоста, лимит скорости.

Не проверено: запуск на Windows и macOS (нативы собираются), звук в самой
игре (в среде проверки нет OpenAL), KVM/WHPX-ускорение.
